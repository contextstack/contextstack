# SCHEMA — the contracts (spec, task, ledger row)

This file plus the specs must be enough to rewrite the runner in a day.

## Spec (`specs/*.yaml`)

- `id` — unique slug; archived specs keep theirs forever.
- `model` — gateway name or executor template; required (PINNED `pinned:` is the default to copy; enqueue and scripts/check refuse its absence). Never a provider URL. The executor runs a template only when `model` names it or the hypothesis does (`ops/bin/_executor.py` `names_executor`).
- `profile`, `capabilities`, `authorization` — DESIGNED, NOT SHIPPED (audit 09-09: enqueue copies a profile string; tick loads the live spec; no deployment/config binding, no route_sha). Intended: enqueue/tick resolves to a SCHEMA-legal record the runner never sees; authorization.usd cannot be enlarged by a model-authored request.
- `system` — prompt path in `prompts/`. `context` — mounted deck.
- `tools`, `post_turn`, `pre_tool`, `mcp` — deny-by-default; empty = none.
  Hook kinds and their exit-code contract: Hook, below.
- `budget` — `{turns, tool_calls, usd, seconds}`, flow or block style (read as YAML; the Director sets `usd` in place); `check_window` default 60. Claude/macOS spec-bound CLI limits use native turns/usage USD and parent-owned native-tool admissions; missing native turns remain null. Zero USD/tool caps retain the runner's unlimited convention. Other CLI adapters have no new enforcement claim.
  Paid admission (DESIGNED, NOT SHIPPED — audit 09-09: only prototype cells existed; enqueue/tick/gateway callers not integrated; gateway discards max_usd; runner sends no ceiling): remaining, reserve, reconcile. Until integrated, no automatic paid selection is claimed.
- `env` — a REQUEST for environment names, resolved by the launcher (`tick`, `run-spec`; `ops/bin/_env_policy.py`) against the node policy `policy/env.json` (rules tier, `{version, always, on_request}`: `always` reaches every tool, hook and op child; `on_request` is what a spec may ask for). Effective = `always` ∪ (`env` ∩ `on_request`), handed to the runner as `CS_CHILD_ENV`; a request in neither tier is refused before any cell runs (`env "NAME": not allowed by policy/env.json`; run-spec exit 2, tick a config-void trial `stop: env_policy: …`). The runner inherits `CS_CHILD_ENV` or, without a launcher (direct `cs-harness run`), its compiled default, which equals the committed `always` and honours no request; file absent = that default. `finalize-run` gives the check and publisher `always` only.
- `tasks`, `trials`, `hypothesis`. `verdict` — archived only. `hypothesis` is prose.

## Task (a directory under `tasks/`)

- `goal.md` — model-facing stimulus only. No comments, provenance, or autopsy.
- `notes.md` — cs-facing; never mounted. Corpus lanes declare `repo:`, shared `setup:`, `writes:`, and `external_effects:` here.
- `solution/` — cs-facing red/green overlay; never mounted; excluded from task_sha.
- `setup/` — files copied into a fresh workspace; corpus lanes may symlink one refreshed cache per destination.
- `check` — executable, cwd = workspace, exit 0 = pass. Mechanical, verify-only. Source checklib.sh: required_path, route_equiv (name is the contract), pest_class; bans (candidate-diff files only; never.git/inherited): assertSee false, assertSee w/o 200, --columns, @test, $var, \\u003c, home-path.
Repo task: `scripts/mktask-repo <name> <repo> <ref>` writes goal.md from stdin, setup/ = `git clone --depth 1 file://<repo> -b <ref>`, and a check that runs that repo's tests scoped to packages the workspace diff touches.
Regression tasks live in `tasks/regressions/` and name the ledger row that spawned them in notes.md.

## Tool (a file pair in `tools/bin/`; a shipped one, listed in `tools/manifest.json`, also carries `<name>.fixtures/` run by `scripts/tool-fixtures`, and every descriptor names its `runtime`)

- `<name>` — executable: args JSON on stdin, cwd = workspace, stdout+stderr = observation; nonzero = error feedback, not a stop. A `runtime: exe` descriptor has no executable here: it names `bin` (relative to the repo holding the code root, else absolute; never from the model) and `args` (strings), and both runners exec CS_TOOL_PREFIX's words + bin + args, cwd/stdin/env/timeout unchanged; cs-sandbox finds such a descriptor by bin + args.
- `<name>.json` — MCP's tool definition fields (`description`, `inputSchema`) plus cs keys (`runtime`, `sandbox`, `image_out`, `timeout_seconds`, `provenance`, `bin`, `args`); `name` is the file stem. The runners send `{name, description, schema: inputSchema}` (WIRE key unchanged) and read a legacy `schema` for one transition release; scripts/check 1d refuses `schema`/`input_schema`/`input`. `image_out: true`: stdout is one JSON object `{text, image{media_type, base64}}` (the tool reads and encodes its own file); the runner forwards `text` plus the neutral image block the gateway translates (modelgateway WIRE Images), never reading or encoding bytes itself; any other stdout is the error observation `<name>: image_out expects {text, image{media_type, base64}}`. Rust limits the combined stdout and stderr of an image tool to 16 MiB (16,777,216 bytes, including the JSON envelope). Larger successful replies become text errors without the image data. Go has no equivalent size limit. New tool = new file pair; the runner never grows for one.

## Hook (`hooks/bin/<name>`)

Executable, cwd = workspace, env `CS_CHECK`, killed after `check_window`. Two kinds, each a spec list; a name not in `hooks/bin` refuses the run at load (`<kind> "<name>": not in hooks/bin`). No sidecar required.
- `post_turn` — after each turn, every listed hook runs, no stdin. Nonzero injects stdout as a user message and refuses stop=done.
- `pre_tool` — before each tool call (listed in the palette or not), in spec order, stdin `{name, args}`, env `CS_TOOL=<name>`; the first nonzero exit decides. Exit 1 (any nonzero but 2) vetoes the call: the tool does not run, the model gets the error observation `pre_tool <hook> refused: <stdout>`, the call counts against `tool_calls`, the loop continues. Exit 2 aborts the run: stop=aborted, the check still runs, the row lands. `step-confirm` is the shipped human-in-the-loop hook: prompts `→ <name> <args>` on `/dev/tty` (`CS_STEP_TTY` overrides; a regular file is consumed one line per call), Enter runs, `q` aborts; no terminal = exit 2, so a dispatched spec aborts rather than running blind.

## Grant (`grants/<id>.yaml`)

`director-operations` grants bind id/estate/ops/expiry/status plus delivery_bindings; they authorize calls, never destination writes. Destination grants: `id`, `repo`, `paths`/`gates` (string lists), `commit` (YAML bool),
`expiry` (RFC3339 UTC), `status` (active|revoked). enqueue/executor
load by id. Dest writes refuse without an active unexpired grant covering repo+paths with commit true. Work orders name their task and grant. Gates run before application in an isolated prospective destination; tasks/ commands resolve in ContextStack, other commands relative to that candidate. Only the identical frozen task check on the identical candidate tree may reuse its original successful result. A durable finalize_gates record binds run/evidence/candidate/expected_head/dest/grant digest; absent, failed, timed-out or mutating gates refuse. None remains legal with a grant; operator_close records a decision without executing a merge.

## Op (`ops/bin/` pair — operator-called, never palette)

JSON in, JSON out (last line). Exit 0 ok; sidecar is the shape.
Never palette. Harvest: per-run `cs/<task>-<runid>`, never `.cs-*`.
Executor dest merge parked. Dispatch: first-terminal-wins;
per-resource flock; seats count job processes only. API and CLI work orders share gateway deployment admission (local-coder tested capacity 4). queue_wait_ms is separate from per_call_latency_ms; whole ContextStack jobs report work_order_latency_ms. Config/credential void holds the schedule (no retry). Tick sweeps unheld cs `.git` and run-workspace `*.lock` files (>2s) during housekeeping. DESIGNED, NOT SHIPPED (audit 09-09): enqueue/tick resolve profile/capabilities/authorization and bind deployment+config hash before either path; capture-stimulus persists that binding. Every non-ignored path is facts or rules (grants=rules, judgments/archive/docs/dev=facts, work/sweep goal/check/notes=rules); hooks classify staged paths before authorizing a red-check exception. A rules-tier commit past a red check must start `check-red:` naming parsed FAIL lines. Ops caps: SUSPENDED to measurement 2026-09-09 (INVARIANTS); last enforced balance 43 executables / 12,040 lines (amendment #3). Ops-cap-state footer still required on rules commits; cap-debt markers optional until trigger caps-enforce.
Lifecycle (contract `lifecycle-v1`): capture-stimulus freezes the consumed goal/check/spec/prompts under `ledger/runs/<run>/stimulus/` before the first call — adapters read those bytes, never the live task; the runner sends runner_implementation and runner_path, and capture-stimulus records runner_build and sandbox_build (`sha256:<hex>` of the runner and of CS_TOOL_PREFIX's first word), tool_builds and hook_builds (`{name: sha256:<hex>}` over the sent `tools`/`hooks`: executable, descriptor or hook.json, and for python3 tools every local import scripts/node-bundle's walk reaches, named by tool_builds_basis) — JSON null when unreadable or unset, never a refusal — in the manifest and reply, bound into env_sha; outside env_sha the manifest also records runner_path and `gateway` {endpoint, implementation, version} from the /v1/health of the `gateway_endpoint` the Rust runner sends, which finalize-run copies to the row as `executed_by` {runner {kind, path, sha256}, gateway} and `ops/bin/run-identity` reports; terminal.json copies runner_build only; the pinned route as an execution artifact (deployment + config hash) is DESIGNED, NOT SHIPPED (audit 09-09). An unavailable bound deployment fails explicitly or records an authorized transition. publish-evidence writes the full candidate diff against the recorded base. Three hashes: task_sha, stimulus_sha, evidence_sha. actor_kind is `human|automated` and is never defaulted. Scoring eligibility is one predicate (`_shadow_eligibility`).
Grounding (ruled 09-08): a claim traces to hash-bound evidence of the kind the claim needs; a web fetch is one kind. Structured sources are registered in ops/bin/snapshot-kinds.json (provenance row, quotable fields, landing files, counted); unregistered kinds get no allowance.

## Estate rows (separate append-only shelves)

`ledger/*.jsonl`: append-only; new rows require local `ESTATE` after the immutable `ledger/estate-cutover.json` prefix. Historical rows without estate belong to their ledger repo; cross-estate refs include the estate and identifier. prod-1 starts empty (counters/triggers restart). `ledger/check-red.jsonl` records Git hook authorizations and landed exceptions. Schedules append `schedule_updated` revisions; readers use latest id. `ledger/ledger.jsonl` carries
trial + applied/operator-close. cost_class is free_local|subscription|api, recorded as the gateway sent it; the gateway applies the class rule and returns cost.est_usd (the rate estimate) and cost.charged_usd (wallet: provider charge when known, else the estimate when api, else 0) as numbers, which the runner only sums into est_usd and cost_usd; an ok response without both numbers is a gateway error (`error: gateway omitted cost numbers (WIRE Response cost)`, verdict void).
est_usd is the agent's API list price (Claude total_cost_usd: est_basis `api_list`, an estimate, never a charge; `metered` on older rows), else token rate (cache writes at the rate, cache reads at 0.1x: `rate`), else prompt chars (`chars`). Executor rows add what the agent reports (ops/bin/_est.py): input_tokens (excluding cache reads), output_tokens (including reasoning), cache_read_tokens, cache_creation_tokens, reasoning_tokens (null when not reported, never 0), reported_model (the real model; `model` stays the alias), allowance {via, rejected, windows [{window, used_pct, resets_at, status}]}, codex_thread. Tail never drops.
## Finalization (`ops/bin/finalize-run`; the only writer of check, transcript, evidence, row)

Input `{run_dir}` under `ledger/runs` holding `terminal.json`, fsync'd with the run dir on entry. Steps in order, each skipped only when its complete output exists, every artifact temp+rename in the run dir: `check.json` {verdict, exit_code, output, window, stimulus_sha, skipped} (void input: skipped; a retry never reruns the check; an existing file whose stimulus_sha differs from terminal.json's is pending, a fixture failure), `transcript.md` (`render`: the body from `messages.jsonl` with the pre-1b runner's format strings, `existing` when a body is already there, `empty` when neither file exists; then the footer), `publish-evidence` (complete = `ready_for_inspection`, or a manifest whose capture_state is not `complete`, which is never marked; a complete manifest without the marker is re-published, idempotently; no `stimulus/manifest.json` = nothing to publish, `skipped`), the ledger row (scan `ledger.jsonl` for this run's `transcript` under the lock, append once, bytes as the Go encoder wrote them; `row_version: 2` adds `error` {class, code, source, retryable, detail} when the stop is an error and `call_errors` {class: count} over failed tool events, and `sandbox` {class: [tool]} naming the tools classed sandbox_denied (a heuristic over the cs-sandbox reports the launcher's per-cell `--report-dir` <state>/sandbox-reports/<cell> collects; finalize-run first moves those whose cwd is the run's workspace into `sandbox/`) or sandbox_unenforceable, vocabulary `error-v1` in ops/bin/_errors.py, whose `row_error` classifies a keyless (version 1) row's stop on read; stop/verdict unchanged), the envelope `<state>/outbox/<run_id>.json` {event_id `run_finalized:<run_id>`, row_sha256, files [{path, bytes, sha256}] over terminal/messages/check/transcript/stimulus/evidence/sandbox, envelope_sha256, `sandbox` summary; a differing recompute is pending, never overwritten}, `finalized.json` last {ts, steps, verdict, stop, scan_rows, scan_ms, error_class}.
One exclusive flock on `finalize.lock` for the whole op; a second finalizer acts on nothing and exits 3 `state: pending`; `finalized` is reported only when `finalized.json` exists. Publish failure or a missing `ESTATE` writes `finalize.error` {ts, error, class (`spool_full` on ENOSPC, else null)} and exits 3; a publish failure still appends the row. `FINALIZE_RUN_CRASH_AFTER=check|transcript|publish|row|envelope` and `FINALIZE_RUN_ENOSPC_BEFORE=row|envelope` are TEST-ONLY fault injection. A dir with `terminal.json` and no `finalized.json` is unfinished finalization, by definition.
tick: a trial with no fresh row, or a runner exit 3 (a failed publish still appends the row), runs `finalize-run` once on this spec's unfinished dirs; a finalized dir closes the job on its row, otherwise completion is withheld and the dispatch TERMINAL row is `state: error`, `code: 3`, `verdict: void`, `stop: finalization_pending` with run_id/transcript from terminal.json (same class as `orphaned_running`; the ledger row arrives when the sweep finishes). `finalize_sweep` runs beside `sweep_stale_locks` every tick on unfinished dirs older than 60 s and reports `finalize_sweep: {attempted, finalized, pending}`; then `ops/bin/spool-send` (policy/spool.json `receiver`: null until phase 6 = sends nothing, counts the outbox; `dir` = copy, receiver verifies every sha256, then ack). Below `min_free_bytes` on the state root tick admits nothing (dispatch `yield` row, class `spool_full`). Dispatch error rows carry the same `error` object (orphaned_running = `node_restart`). Fleet node (CS phase 6): `receiver: {kind: director, url, node, token_env}` makes tick run only node work (finalize_sweep, recovery, `ops/bin/job-pull`, spool-send; no triggers, shadow, schedules, audit); its shelves (`dispatch.jsonl`, locks, heartbeat) live under the state root; job-pull materialises a director job's sha256-verified bundle once in `<state>/jobs/<job>/` (whose relative prompts capture-stimulus resolves there), queues it once, then accepts; spool-send POSTs each envelope and each director job's terminal row (`job_terminal:<job>`, written by tick) to the director's node API and moves it to `outbox/acked/` only on an ack naming its envelope_sha256; `retention: prune_acked` deletes a workspace only after an ack with the run restored. A job may carry `grants/<id>.yaml` (hashed into the bundle): job-pull enforces it (active, unexpired, `estate` = the node's ESTATE) before queueing, else closes the job `grant: …` (`node_config`); a schedule naming `node` is fired by schedule-tick through `CS_DIRECTOR_DISPATCH` and closed from `CS_DIRECTOR_ESTATE_ROOT/dispatch.jsonl`, its grant's estate naming the node. Every shelf path resolves through `_estate_io.state_dir` (`<code-root>/ledger` unless `CS_STATE_ROOT`).
## Runner obligations (what `cs-harness run` must do, nothing more)

0. One cell. `cs-harness run [-task dir] [-trial N] <spec>`: task = `-task`, else the spec's only task (several listed and no `-task`: exit 2 naming `ops/bin/run-spec`); trial = `-trial`, else `CS_TRIAL`, else 1; stdout is the one line `<id> <task> t<n> <verdict> stop=… turns=… tools=… $…`.
   Whole-spec iteration (tasks × trials), the banner `<id>: N task(s) x M trial(s)` and the `TOTAL p/w pass` line are `ops/bin/run-spec` {spec, task?, trials?} (argv `<spec> [-task dir]` at a terminal): one `cs-harness run -task T -trial n` per cell, output forwarded; exit 3 if any cell did, else 1 if pass < want. tick passes `-trial` and still sets `CS_TRIAL` for capture-stimulus and tools.
1. Load the resolved execution record; refuse unknown fields — they hide features.
2. Copy task `setup/` into a fresh workspace; mount `context` files.
3. Loop: gateway → pre_tool hooks → tools → post_turn hooks → done or budget. SIGINT: stop=interrupted, verdict=void, still the tail. On timeout or cancellation the Rust runner kills the tool or hook process group before finalization. The built-in `step-confirm` hook runs in the foreground group for terminal access.
4. Append `messages.jsonl` as it goes (one JSON event per line, no HTML escaping, durable per event so a crash leaves a readable prefix: `header` {spec, task, trial, model, budget{turns, tool_calls, usd, seconds}}, `turn` {turn, text}, `tool` {turn, name, args, error, content}, `post_turn`|`pre_tool` {turn, output}, `error` {turn, error}; never `transcript.md`, which is finalize-run's rendering of it), then write `terminal.json` (temp+rename: run_id, run_dir, transcript, workspace, stimulus_dir, spec, spec_sha, spec_path, task, trial, task_sha, env_sha, stimulus_sha, model, stop, verdict input (`void` on interrupt or `error:`, else empty = run the check), turns, tool_calls, cost_usd, est_usd, est_basis, cost_class, started, ended, seconds, check_window, runner_implementation (`go` or `rust`), runner_build (copied from capture-stimulus's reply)), then call `finalize-run` and take verdict/stop from its reply. Exit 3 plus one stderr line `cs: finalization pending: <run dir>` when it does not report `finalized` (1 = the cell did not pass, 2 = usage/load error); a pending cell never counts as passed.
   Each `prompt` record contains `turn`, the zero-based message index `from`, and the `messages` appended since the previous prompt, so the full prompt is the concatenation of all prompt deltas through the record referenced by that turn’s span.
Repair setup: notes.md `repair_run` + `repair_evidence_sha` bind the frozen input; setup-refresh verifies and reapplies it on every dispatch, excludes private runtime files, and refuses a changed base.
