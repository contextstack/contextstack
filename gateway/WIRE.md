# WIRE — the gateway's constitution

`agent.gateway.model_call.v2` is the current caller contract. It is the same byte shape as frozen legacy `cs.gateway.model_call.v1`; only the required discriminator changed. Additive fields stay in their version (absent means previous behavior). Anything else bumps the version, announced to cs first — never drift. The v1 compatibility contract and its counted retirement gate are specified under Migration below. Capped at 120 lines; governs over any refactor doc. Shape sketch: cs/internal/cs/run_test.go (fakeGateway, turnOK). Transport: HTTP on `CSGATEWAY_PORT` (9200); optional unix socket `CSGATEWAY_SOCKET`, same routes and auth, 0600; loopback-only routes refuse over it. `CSGATEWAY_MAX_INFLIGHT` (256, min 1) caps concurrent HTTP connections; when full, new connects wait 5s then `503` `gateway.busy`. Request headers must arrive within 10s.

## Request

- `schema_version: "cs.gateway.model_call.v1"` — required; checked.
- `messages[]` — role user|assistant|tool. Content is a string, or content blocks (see Images). Optional assistant `tool_calls: [{id,name,args}]` pairs with tool `tool_call_id` + `is_error`; absent IDs retain legacy text.
- Images: content blocks. The Anthropic-shaped block `{"type":"image","source": {"type":"base64","media_type","data"}}` passes verbatim. Additive (cs adoption pending): the neutral block `{"type":"image","media_type":<mime>,"base64":<data>}` with no `source`, in tool or user content. anthropic translates it to the `source` shape, byte-equivalent to the verbatim block; openai_compat refuses it exactly as clause 3. A neutral block missing `media_type` or `base64` is a request error: `gateway.invalid_image_block`, fatal_session, $0, before any provider call.
- Optional trace identity: `job_id`, `run_id`, `step_id` (turn number), `request_id` and `send_index` (one-based, default 1). A traced caller uses `run_id` as the trace ID and `request_id` as the model-call span ID. The gateway appends JSONL records under `~/.contextstack/gateway/traces/`, grouped by run ID or UTC date for requests without a run ID.
- `tool_choice` — optional OpenAI-compatible tool selection. OpenAI-compatible adapters forward it. Anthropic maps a named function to its encoded tool name and `"required"` to `{"type":"any"}`. An unsupported choice is omitted and marked `tool_choice_dropped` on the gateway exchange trace.
- `tool_schema[]` — name, description, input schema. Live decoder and cs use this name (not `tools[]`).
- `capability.model_tier_hint` — routing input; the gateway resolves, the caller never learns routing internals from errors. Empty hint selects `free_local` (`local-coder` first); API requires an explicit name. Ratified v1 routing amendment — no new fields.
- `budget.timeout_ms` — HTTP deadline. `budget.max_output_tokens` — sampling (used). `budget.max_input_tokens` — accepted, copied onto Invocation, not enforced. `budget.max_usd` — decimal string, a ceiling: it only lowers. Source budgets: an api call's source is its catalog endpoint id, OFF unless `~/.contextstack/config/gateway/limits.json` `sources.<id>` or the shared `sources."*"` is `{usd > 0, period: day|month}` (legacy `api_usd_per_day: X` = `"*"` daily). Before any connection its reservation (⌈body bytes/4⌉ × input rate + max output × output rate from `models.json` `rates` per 1M or `cost_per_1k`) must fit `max_usd` and each budget's usd − spend − in-flight holds (concurrent calls cannot jointly exceed); else `fatal_session` `gateway.policy_denied`, $0, with `error.budget.reason` off | exhausted (with `resets_at`) | ceiling | invalid (fail closed). Spend per source, day and month: `~/.contextstack/gateway/spend.json`. `GET /v1/budgets`: each source off|active|exhausted, no keys; `PUT` replaces the file (invalid writes nothing) only with `X-ContextStack-Owner-Token` = `~/.contextstack/config/gateway/owner-token` (made 0600 at first start) from loopback or the socket; the shared token never suffices. Local and subscription calls skip dollar-budget admission. Positive provider-reported charges on any route debit the applicable budgets. API admission is off by default.

## Response (status ok)

- `status: "ok"`, `schema_version` echoed.
- `model` — the RESOLVED model name, echoed. ContextStack tests assert it; rows record it; silent substitution is the named original sin.
- `message: {role: "assistant", content, stop_reason}`.
- `tool_calls[]: {id, name, args}` — parsed to structure regardless of the provider's native tool dialect. Invalid native OpenAI-compatible argument JSON yields `args: {}, invalid_arguments: true` on that call. Valid sibling calls and usage still travel in the reply.
- `usage: {input_tokens, output_tokens}` — integers; cache tokens affect `cost` only.
- `cost: {currency: "USD", amount: "0.010000", class}` — amount is a decimal STRING (list-price sum of input, output, cache_read and cache_write at per-model rates, unary/stream). `class` is additive v1: free_local|subscription|api; omitempty = previous behavior. Additive: `est_usd`, `charged_usd` — plain JSON numbers on every ok response and stop chunk. A terminal error with a settlement carries its `cost`, including `charged_usd`. A paid request sent and then aborted by deadline, disconnect, or connection loss settles at the reservation unless the provider reported a positive charge. The trace marks a reservation estimate. est_usd is the estimated cost. On completion, charged_usd = `charged` when present else est_usd for api else 0; `over_reservation` when settlement beat the reservation (true charge always counted toward the budget).
- Stream (`stream: true`, SSE; additive): delta chunks, then one terminal. The stop chunk carries `provider`, `model`, `stop_reason`, `tool_calls` (same parse rules), `usage`, `cost`: delta text + stop == the unary reply. An endpoint whose protocol ∩ declaration cannot stream (`streaming` on /v1/models and /v1/capabilities) refuses `fatal_session` `gateway.streaming_unsupported`, $0, before any connection; a policy refusal stays `gateway.policy_denied`.
- CLI work orders (`POST /v1/agent/cli.run`; additive, Director.Plan step 5): optional top-level `execution_id` (1–128 of `[A-Za-z0-9._:-]`, else 400; one still running is 409 `execution_in_use`; absent, `environment.CS_JOB_ID` when free, else `lx-…`), echoed in `X-ContextStack-Execution-Id`. `POST /v1/agent/cli.run/{id}/cancel` (`id`: execution id or CS_JOB_ID, every running trial of that job; optional body `{reason}`, logged as a `cli_cancel` row) takes cli.run's rule (bearer when set, loopback TCP, never the socket) and, for a run started with `X-ContextStack-Caller`, only that caller (else 403 `not_owner`); it TERMs the process group, KILLs after the termination grace (18 s for receipt children, otherwise 5 s), releases the permit, then answers `{cancelled: true, result: cancelled}`; an ended run `{cancelled: false, result: already_finished, outcome}` (completed|cancelled|failed|abandoned); unknown 404 `unknown_execution`. The cancelled call ends 200 `{stdout, stderr, exit_code: -1, outcome: "cancelled"}`: output so far, not a fault (the gateway meters no work-order cost; the agent's own report is in stdout). `stream: true` is SSE `agent.gateway.cli_run.chunk.v1` (`execution_id`, `index`): `delta` `content` mapped from the agent's own stdout events (claude stream-json, codex `--json`, gemini stream-json; text only), then one `stop` whose JSON `result` equals the unary reply, or an `error` chunk (`status`, unary text). The reply retains up to the last 8 MiB each of stdout and stderr. Live deltas may be skipped when the client falls behind. Other executors refuse one `fatal_session` `gateway.streaming_unsupported` chunk before admission, $0.
- Machine CLI jobs request an execution receipt. Send a top-level `receipt: {"run_id": "...", "trial": 2}` with an explicit `execution_id`, a nonempty `X-ContextStack-Caller`, and valid `environment.CS_JOB_ID` and `environment.CS_TRIAL`. The trial must match the positive integer `work_order.trial`. The run ID names one directory already reserved by the harness under `CS_STATE_ROOT/runs`. A terminal result includes `receipt` with the [version 1 execution receipt](../cs/ops/EXECUTION-RECEIPT.md) produced by the executor in execution-only mode. The outer `exit_code` is the configured executor's process exit. The gateway binds the receipt to its registration and reads native metadata from a private channel owned by the trusted executor. It never interprets agent stdout as receipt metadata. The receipt is null when cancellation, a deadline, or executor failure prevents receipt production. Malformed private metadata, or missing metadata on a successful exit, is a 502 (an SSE error when streaming). A supervisor deadline after launch produces a terminal result with `outcome: "timed_out"` for receipt callers. Without opt-in, the reply has its existing shape and deadline behavior.
- The machine `executor` launcher starts the harness, then hands the returned receipt to `machine-finish` after the harness exits. The configured node executor runs only in execution-only mode with a receipt binding. The child writes `events.jsonl` as the CLI streams, so node-listen can forward output while the harness is still running.
- `cs-harness cli-run < work-order.json` reserves the UTC run directory, binds the execution to `CS_JOB_ID` and the trial, and calls the configured `CSGATEWAY_CLI_ENDPOINT` (default `http://127.0.0.1:9200/v1/agent/cli.run`). It uses `CSGATEWAY_AUTH_TOKEN` when configured and sends `CS_GATEWAY_CALLER` (default `harness:<job_id>`) on launch and cancel. Live deltas go to stderr and the correlated execution outcome goes to stdout as JSON. The command exits zero when it emits an outcome, including execution failures. The only automatic resend is the unary fallback after an explicit `gateway.streaming_unsupported` response before dispatch. A stream that closes before its terminal event yields `transport_lost`.

## Hard-won clauses (each has a ledger receipt; each is a characterization test in any refactor)

1. **Unknown model refuses** — distinct error class (`gateway.unknown_model`), $0 spent, never a fallback provider, never a mock. Settled law since the silent-misroute incident. A model in inventory whose provider is not registered refuses `fatal_session` `gateway.provider_not_configured` (not retryable).
2. **Hermes XML → tool_calls** — openai_compat parses XML-dialect tool calls into the structured field (promoted).
3. **Images**: anthropic passes content blocks verbatim (neutral block translated, see Request); openai_compat REFUSES image blocks fail-closed, neutral or native, same error class — unchanged by the addition.
4. **Transport death is distinguishable** from an empty-but-ok response — cs maps `error:` stops to verdict `void`; an EOF that looks like success corrupts the ledger. A stream that ends without a stop event is `gateway.transport_failed`, not ok.
5. **Errors carry a machine-readable class**, never a partial result, and cost $0 unless they carry a settlement under Response. Permanent upstream refusal (`gateway.provider_request_rejected`) and quota exhaustion (`gateway.provider_quota_exhausted`) are `fatal_session`. Transient upstream HTTP responses and connection establishment faults before dispatch are `retryable_gateway` with optional `retry_after_ms` for every provider. A connection close or reset before complete response headers can trigger up to two replays of a dispatched POST only for a target with catalog cost class `free_local`, for both unary calls and stream opens. If those retries are exhausted, the close or reset is `retryable_gateway`. A dispatched paid request that loses its connection returns `gateway.transport_failed` and settles once because replay could double-bill. Once a stream opens, transport failures never trigger a replay. Upstream HTTP error bodies are not replayed on the wire except a plain provider `error.message` string under 300 characters.

New fields: additive only within v1, absent-means-previous-behavior. Anything else: bump the version, land a cs-side probe first. Empty-hint → free_local is a v1 routing amendment (field set unchanged). Gate fails on void, `error:` stop, wrong/mismatched resolved model, nonzero cost on a $0 model, or unequal pass-rate across ports. Turns/tools may differ. Stream unknown-model is :9201-only.

## Migration: agent.gateway.model_call.v2

The pre-cs CS protocol generation is retired; the new Rust `cs` uses Agent v2. `agent.gateway.model_call.v2` is byte-for-byte the `cs.gateway.model_call.v1` JSON payload shape — same request fields, same response fields, same chunk fields. It is `v2` only because the required `schema_version` discriminator value changed; no field was added, removed, or renamed.

- `/v1/agent/model.call` and the temporary `/v1/cs/model.call` alias both accept `cs.gateway.model_call.v1` and `agent.gateway.model_call.v2` on `schema_version`. Neither the route nor the v1 schema is removed yet.
- Unary success and envelope errors echo the request's accepted schema_version. A `schema_version` that is neither v1 nor v2, or a body that fails to decode at all, has no accepted version to echo and reports under the v2 family.
- SSE frames carry the matching chunk family: `cs.gateway.model_call.chunk.v1` for an accepted v1 request, `agent.gateway.model_call.chunk.v2` for v2. Malformed JSON and schema mismatches return a JSON error envelope under the v2 request family.
- The five hard-won clauses above hold identically in both families — they are schema_version-agnostic.

The cutover is measured, not assumed. Every accepted (v1 or v2) request logs one `wire_request` row — schema_version, caller (`X-ContextStack-Caller` trimmed, else `role.role_pack_name`, else `unknown`), path, request_id — recorded after schema acceptance, before message/model validation, so envelope errors count too. `GET /v1/health` → `wire_cutover`: totals by schema and caller+schema, `consecutive_v2`, `threshold: 500`, `ready` (true at 500 consecutive v2 requests; v1 resets it) — retire v1 only once `ready`.
